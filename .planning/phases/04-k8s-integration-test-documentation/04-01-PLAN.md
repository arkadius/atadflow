- **IMPORTANT:** The `withHelm3()` runs DURING container startup. But we need to load the Docker image BEFORE Helm install. The K3s Helm3 API runs as part of container initialization, which means image loading cannot happen before it. To solve this:
  - Do NOT use `withHelm3()` for Helm install.
  - Instead, start K3s container plain, then in `@BeforeAll`:
    1. Start K3s container
    2. Load image into K3s
    3. Install Helm chart via `k3s.execInContainer("helm", ...)` commands
  - Actually, check if K3s container has Helm pre-installed. If not, use Fabric8 client to apply rendered templates. **Preferred approach:** Use `k3s.execInContainer` to run `helm` commands since the K3s image with Helm3 support should have Helm available.
  - **Simplest correct approach:** Use a static K3s container with manual lifecycle in `@BeforeAll`/`@AfterAll`. Do NOT use `@Container` annotation (which auto-starts). Instead:

```java
static K3sContainer k3s = new K3sContainer(DockerImageName.parse("rancher/k3s:v1.30.6-k3s1"));

@BeforeAll
static void setUp() throws Exception {
    k3s.start();

    // 1. Export Docker image to temp file
    Path imageTar = Files.createTempFile("atadflow-image", ".tar");
    new ProcessBuilder("docker", "save", "atadflow/atadflow:1.2.0", "-o", imageTar.toString())
        .inheritIO().start().waitFor();

    // 2. Load image into K3s containerd
    k3s.copyFileToContainer(MountableFile.forHostPath(imageTar), "/tmp/atadflow-image.tar");
    k3s.execInContainer("ctr", "images", "import", "/tmp/atadflow-image.tar");
    Files.deleteIfExists(imageTar);

    // 3. Install Helm chart via Fabric8 client or kubectl
    // Use helm commands via exec
    // First, add bitnami repo
    k3s.execInContainer("helm", "repo", "add", "bitnami", "https://charts.bitnami.com/bitnami");
    k3s.execInContainer("helm", "repo", "update");

    // Copy chart directory into container
    k3s.copyFileToContainer(MountableFile.forHostPath("chart"), "/chart");

    // Helm dependency update + install
    k3s.execInContainer("helm", "dependency", "update", "/chart");
    k3s.execInContainer("helm", "install", "atadflow-test", "/chart",
        "--set", "postgresql.auth.password=testpass",
        "--set", "securityContext.readOnlyRootFilesystem=false",
        "--set", "image.pullPolicy=Never",
        "--wait", "--timeout", "3m");
}

@AfterAll
static void tearDown() {
    k3s.stop();
}
```

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: "{{ include "atadflow.fullname" . }}-test-api"
  labels:
    {{- include "atadflow.labels" . | nindent 4 }}
  annotations:
    "helm.sh/hook": test
spec:
  activeDeadlineSeconds: 120
  restartPolicy: Never
  containers:
    - name: curl
      image: curlimages/curl:8.5.0
      command:
        - sh
        - -c
        - |
          echo "Testing health endpoints..."
          curl -f http://{{ include "atadflow.fullname" . }}:{{ .Values.service.port }}/q/health/live || exit 1
          curl -f http://{{ include "atadflow.fullname" . }}:{{ .Values.service.port }}/q/health/ready || exit 1

          echo "Testing API endpoints..."
          curl -f http://{{ include "atadflow.fullname" . }}:{{ .Values.service.port }}/api/node-types || exit 1
          curl -f http://{{ include "atadflow.fullname" . }}:{{ .Values.service.port }}/api/flows || exit 1

          echo "Verifying node types count..."
          TYPES=$(curl -s http://{{ include "atadflow.fullname" . }}:{{ .Values.service.port }}/api/node-types | grep -o '"id"' | wc -l)
          if [ "$TYPES" -ne "6" ]; then
            echo "Expected 6 node types, got $TYPES"
            exit 1
          fi

          echo "All tests passed!"
      resources:
        requests:
          memory: "32Mi"
          cpu: "50m"
        limits:
          memory: "64Mi"
          cpu: "200m"
```

## Local Development with Telepresence

[Telepresence](https://www.getambassador.io/docs/telepresence) lets you run a local Quarkus dev instance that connects to cluster services (PostgreSQL, Spark Connect), enabling fast code iteration without rebuilding the Docker image.

### Prerequisites

- A running K8s cluster with the Atadflow Helm chart installed
- [Telepresence 2.x](https://www.getambassador.io/docs/telepresence/latest/install) installed locally
- Java 25+ and Gradle for local Quarkus dev mode

### Workflow

```bash
# 1. Connect Telepresence to the cluster
telepresence connect

# 2. Intercept the atadflow service (routes traffic to localhost:8080)
telepresence intercept atadflow --port 8080:http

# 3. Start Quarkus in dev mode (connects to cluster PostgreSQL/Spark via env vars)
cd backend
QUARKUS_DATASOURCE_JDBC_URL=jdbc:postgresql://atadflow-postgresql:5432/atadflow \
QUARKUS_DATASOURCE_USERNAME=atadflow \
QUARKUS_DATASOURCE_PASSWORD=<your-password> \
SPARK_CONNECT_URL=sc://spark-connect:15002 \
./gradlew quarkusDev

# 4. Edit code — changes take effect immediately via Quarkus live reload
# All cluster traffic to the atadflow service routes to your local instance

# 5. End the intercept when done
telepresence leave atadflow
telepresence quit
```

### Notes

- DNS resolution for cluster services (e.g., `atadflow-postgresql`) is handled by Telepresence
- VPN users: Telepresence may conflict with VPN routes. Disconnect VPN during intercept if you experience connectivity issues
- For frontend development, run `cd frontend && npm run dev` separately (Vite proxies to localhost:8080)
```
