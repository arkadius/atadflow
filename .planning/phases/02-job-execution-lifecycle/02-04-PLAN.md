<objective>
Fix the cancel functionality so that cancelling a job actually stops Spark streaming queries on the Spark Connect server, not just kills the Python client process.

Purpose: Currently, killing the Python process leaves streaming queries running on the Spark Connect server because the generated Python code has no signal handler. SIGTERM kills the process without giving it a chance to call query.stop() on active queries. This plan adds signal handling logic to the generated Python code.

Output: CodeGenerationService generates Python code with signal handlers that collect StreamingQuery references, register SIGTERM/SIGINT handlers, and call query.stop() on all active queries before exiting gracefully.
</objective>

- Use pattern: `query_N = {existing_code}.start()` then `streaming_queries.append(query_N)`
- This captures StreamingQuery references so they can be stopped in the signal handler

**Replace awaitAnyTermination with interruptible pattern:**
- Current: `spark.streams.awaitAnyTermination()`
- New: Wrap in try/except to catch KeyboardInterrupt and call signal handler
- Pattern:
  ```python
  try:
      spark.streams.awaitAnyTermination()
  except KeyboardInterrupt:
      handle_shutdown(None, None)
  ```

**Generated code structure:**
```python
from pyspark.sql import SparkSession
from pyspark.sql.functions import *
import signal
import sys

spark = SparkSession.builder.remote("sc://...").getOrCreate()

streaming_queries = []

def handle_shutdown(sig, frame):
    print(f"Received signal {sig}, stopping streaming queries...")
    for query in streaming_queries:
        try:
            query.stop()
        except Exception as e:
            print(f"Error stopping query: {e}")
    sys.exit(0)

signal.signal(signal.SIGTERM, handle_shutdown)
signal.signal(signal.SIGINT, handle_shutdown)

# {node code here}

# For write-stream nodes, modify generation to capture query:
# Before: df_write_stream_1.writeStream.format("console").start()
# After:
query_1 = df_write_stream_1.writeStream.format("console").start()
streaming_queries.append(query_1)

try:
    spark.streams.awaitAnyTermination()
except KeyboardInterrupt:
    handle_shutdown(None, None)
```

**Implementation notes:**
- Add signal handler setup right after SparkSession creation
- Modify the code generation loop to detect write-stream nodes
- For write-stream nodes: extract the writeStream code, wrap in query_N variable, append to list
- For non-write-stream nodes: generate code as before (no changes)
- Signal handler must be robust: catch exceptions when stopping queries (query might already be stopped)
- Use sys.exit(0) to ensure clean exit code (SparkSubmissionService treats 0 as SUCCESS)

Why this works: SparkSubmissionService.cancel() already sends SIGTERM correctly. The Python code just needs to handle it, stop the queries on the Spark Connect server, then exit cleanly.
