  <name>Task 2: Rewrite SparkSubmissionService with real subprocess execution</name>
  <files>
    backend/src/main/java/io/atadflow/service/SparkSubmissionService.java
  </files>
  <action>
    Replace the entire stub implementation with a real subprocess executor. The service needs these injected dependencies:

    ```java
    @Inject ManagedExecutor executor;
    @ConfigProperty(name = "python.executable") String pythonExecutable;
    ```

    **submit(Job job, String code) method:**
    - Return type changes from `void` to `void` (keep synchronous -- the method launches the process and returns; async monitoring happens via onExit callback). The reason: JobService.submitJob() is @Transactional and needs the job persisted with RUNNING status before the method returns. Making submit() return CompletionStage would complicate transaction management without benefit since the only async part is monitoring the process exit.
    - Write `code` to a temp file using `Files.createTempFile("spark-job-", ".py")` with `Files.writeString(tempFile, code)`.
    - Create ProcessBuilder: `new ProcessBuilder(pythonExecutable, tempFile.toString())`.
    - Call `pb.inheritIO()` to prevent output buffer deadlock (per research).
    - Start the process: `Process process = pb.start()`.
    - Set `job.processPid = process.pid()`.
    - Set `job.status = JobStatus.RUNNING` and `job.startedAt = LocalDateTime.now()`.
    - Register async exit handler using ManagedExecutor for Quarkus context propagation:
      ```java
      process.onExit().thenAcceptAsync(p -> {
          handleProcessExit(job.id, p.exitValue(), tempFile);
      }, executor);
      ```
    - If IOException occurs during file write or process start, set `job.status = JobStatus.FAILED`, `job.errorMessage = e.getMessage()`, `job.finishedAt = LocalDateTime.now()`, and delete the temp file if it exists.
    - Do NOT delete the temp file immediately after start -- delete it in the onExit callback (per research Pitfall 3: process may not have read it yet).

    **handleProcessExit(UUID jobId, int exitCode, Path tempFile) method:**
    - Must be `@Transactional` since it runs in the ManagedExecutor thread.
    - Load `Job job = Job.findById(jobId)`. If null, just delete temp file and return.
    - If job.status is CANCELLED, skip status update (cancellation already set the status). Still delete temp file.
    - If exitCode == 0: set `job.status = JobStatus.SUCCEEDED`.
    - If exitCode != 0: set `job.status = JobStatus.FAILED`, `job.errorMessage = "Process exited with code " + exitCode`.
    - Set `job.finishedAt = LocalDateTime.now()`.
    - Call `job.persist()`.
    - Delete the temp file in a finally block: `Files.deleteIfExists(tempFile)`. Wrap in try-catch and log warning on failure (don't let cleanup failure mask the real result).

    **cancel(Job job) method:**
    - If `job.processPid == null`: just set `job.status = JobStatus.CANCELLED` and `job.finishedAt = LocalDateTime.now()`, return.
    - Look up process handle: `ProcessHandle.of(job.processPid)`.
    - If present: call `handle.destroy()` (SIGTERM). Then try `handle.onExit().get(5, TimeUnit.SECONDS)`. If still alive or timeout, call `handle.destroyForcibly()` (SIGKILL).
    - Regardless of whether ProcessHandle found (process may have already exited): set `job.status = JobStatus.CANCELLED` and `job.finishedAt = LocalDateTime.now()`.
    - Wrap the ProcessHandle operations in try-catch. Log warnings on failure but always set CANCELLED status.

    **Imports needed:**
    ```java
    import jakarta.inject.Inject;
    import org.eclipse.microprofile.config.inject.ConfigProperty;
    import org.eclipse.microprofile.context.ManagedExecutor;
    import jakarta.transaction.Transactional;
    import java.io.IOException;
    import java.nio.file.Files;
    import java.nio.file.Path;
    import java.time.LocalDateTime;
    import java.util.UUID;
    import java.util.concurrent.TimeUnit;
    ```

    **Important:** Keep `@ApplicationScoped` class annotation. Keep the existing Logger.
